# Website localization

The site supports the shared 50-locale set, combining languages with substantial
computer use and deliberately underserved languages. It is not a ranking by
number of speakers. The owner enabled website localization on October 26, 2026
and approved machine translations while native review remains pending. Publication
notices are selective, following the owner's same-day refinement.

English source pages remain at their existing URLs. Explicit language pages use
`/l/<locale>/`, for example `/l/fr/software/` and `/l/en/software/`.
Each explicit page is static HTML, readable without JavaScript, with its own
canonical URL and alternate-language links. JavaScript only selects a preferred
language on neutral URLs and enhances the picker and interactive features.

Selection order is explicit URL, saved picker choice, ordered browser language
preferences, then English. An English explicit URL always stays English.
Storage failures do not break navigation. The choice stays in the URL even
when private browsing blocks localStorage. There is no IP-based location lookup,
translation request, or third-party script for localization at visitor runtime.
The preference is stored locally under `mecha-language`.

The picker uses native language names. Five languages (`ar`, `fa`, `he`, `ps`,
`ur`) set the document direction to RTL. Locale codes in paths use the shared
underscore convention; HTML language tags use BCP 47, such as `pt-BR` and
`zh-Hant`. Explicit Chinese scripts win over regional defaults.

## Editing and publishing

1. Edit the English source pages and, for dynamic messages, `scripts/runtime-strings.mjs`.
2. Run `nix develop -c node scripts/localize.mjs --extract` to refresh `i18n/en.json`.
3. Translate changed catalog entries into the other 49 JSON catalogs. Keys derive
   from the English text, so a source change requires an explicit new translation.
4. Preserve all HTML tags and their attributes, numeric claims, prices, product
   names and limitations. Inline phrases are translated together, preserving
   context across emphasis and links.
5. Run `nix develop -c node scripts/localize.mjs --write` to regenerate `l/` and
   `assets/i18n/`. These generated artifacts are committed because GitHub Pages
   publishes this repository directly. Never edit generated pages by hand.
6. Stage the intended files, then run `nix build --no-link .#default .#checks.x86_64-linux.test`.

The build verifies that generated pages match the current source and catalogs.
Tests use pure fixture rendering and read-only artifact comparisons; they never
regenerate files in the working checkout. No translation API, key, or network
access is needed to build, test, or serve the site.

## Quality and limitations

Initial translations were drafted with Gemini 2.5 Flash (direct API and OpenRouter), with protected markup
and names, numeric and key-parity checks, plus independent agent review. These
controls do not certify fluency or semantic equivalence. Native-speaker review
remains pending, especially for low-resource languages. Amharic, Hausa, Igbo,
Pashto and Yoruba retain the machine-translation notice and correction link based
on the review's unresolved terminology and fluency concerns. Other locales display
without a translation disclaimer, including Germanic and Romance languages. This
is a site-specific confidence judgment, not a guarantee of error-free prose or
a general ranking of languages. Update `scripts/translation-policy.mjs` when
further review supports changing that set. Legal pages identify the
English original; translations do not introduce new commercial terms.

See the [independent review record](i18n-review.md) for sampled checks,
corrections and the remaining limits of automated review.

The social preview image contains English brand copy; its metadata description
and alternate text are translated. Product names and technical identifiers
remain unchanged. Prices remain the specified US-dollar amounts without currency
conversion. The language preference does not infer a customer's country.
