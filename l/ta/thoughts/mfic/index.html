ஆலோசனை மென்பொருள் தொடர்பு

சிந்தனைகள் · முறையியல்

AI வெளியீட்டை உங்கள் பெயரில் வைக்கும் அளவுக்கு நம்புவது.

MFIC — இயந்திர ரீதியாக-தவறாக நிரூபிக்கக்கூடிய சுயாதீன கட்டுப்பாடு என்பது அதற்கான ஒரு ஒழுக்கம்: ஒவ்வொரு கைமாற்றிலும் சுயாதீன சோதனைகள், அவை ஒப்பந்தம் அல்லது தரவுகளிலிருந்து தங்கள் தீர்ப்பைப் பெறுகின்றன, ஒருபோதும் தயாரிப்பாளரின் கூற்றுப்படி அல்ல, மேலும் நிராகரிக்க அல்லது நிறுத்த அதிகாரம் கொண்டவை. இது Sarbanes-Oxley (COSO) க்குப் பின்னால் உள்ள உள்-கட்டுப்பாட்டு மாதிரி — கடமைகளைப் பிரித்தல், தடுப்பு மற்றும் கண்டறியும் கட்டுப்பாடுகள், தணிக்கை தடங்கள், நியாயமான உறுதிப்பாடு — LLM (அல்லது அவசரப்பட்ட மனிதன்) புதிய நம்பத்தகாத கட்சியாக.

ஒழுங்குபடுத்தப்பட்ட, அதிக ஆபத்துள்ள பணிகளுக்கு, “AI சொன்னது” என்பதற்கும், தணிக்கையின் கீழ் நீங்கள் பாதுகாக்கக்கூடிய பதிலுக்கும் உள்ள வேறுபாடு இதுதான். இது Mecha உருவாக்கும் அனைத்திற்கும் பின்னால் உள்ள ஒழுக்கம் — மேலும் இங்கு ஒரு சரிபார்ப்பு முடிவு ஒரு வாக்குறுதியுடன் அல்லாமல் ஒரு கேட் உடன் வருவதற்கான காரணம்.

தவறு செய்யக்கூடிய ஒரு ஆசிரியர் — ஒரு LLM, அல்லது அவசரப்பட்ட மனிதன் — அமைதியாக சிதைக்கக்கூடிய குறியீடு அல்லது தரவை எவ்வாறு நம்புவது. TDD இன் சிவப்பு கட்டம் F (ஒரு சோதனை தீயை பற்றவைக்க முடியும்) மட்டுமே தருகிறது; MFIC மற்ற மூன்றையும் சேர்க்கிறது. இது COSO / Sarbanes-Oxley உள்-கட்டுப்பாட்டு மாதிரி, LLM புதிய நம்பத்தகாத கட்சியாக.

வரையறை: ஒரு கைமாற்று எல்லை இல் ஒரு சுயாதீன சோதனை, அது ஒப்பந்தம் அல்லது தரவுகளிலிருந்து அதன் தீர்ப்பைப் பெறுகிறது — ஒருபோதும் தயாரிப்பாளரின் கணக்கிலிருந்து அல்ல — மேலும் நிராகரிக்க, நிறுத்த அல்லது வழிநடத்த அதிகாரம் கொண்டது.

லிட்மஸ்: அதே முகவர் சோதனை மற்றும் சோதிக்கப்பட்ட இரண்டையும் எழுதினால், தவறான வேலைகளுடன் அது தேர்ச்சி பெற முடியுமா? ஆம் → ஏமாற்றக்கூடியது, MFIC அல்ல. இல்லை → MFIC.

ஒவ்வொரு வார்த்தையும் சுமை தாங்கக்கூடியது:

  • இயந்திர ரீதியாக — வழக்குகள் இயந்திரத்தால் துடைக்கப்பட்டன, கையால் தேர்ந்தெடுக்கப்படவில்லை. ¬M → விடுபட்ட பிழைகள்.
  • தவறாக நிரூபிக்கக்கூடியது — ஒவ்வொரு வழக்கும் நீங்கள் முன்கூட்டியே ஏற்பாடு செய்ய முடியாத ஒரு கசப்பான மறுப்பு. ¬F → வெற்றிடமான பச்சை சோதனைகள், அல்லது பலவீனமான ஆரக்கிள்கள் ("தவறான வெளியீட்டை மறைக்கும் செயலிழக்காது").
  • சுயாதீனமானது — உண்மை ஆதாரம் தயாரிப்பாளரிடமிருந்து காரண ரீதியாக சுயாதீனமானது (≡ கடமைகளைப் பிரித்தல்: தயாரிப்பாளர் ≠ சரிபார்ப்பவர்). ¬I → ஒரு குருட்டுப் புள்ளியைப் பகிரும் கூட்டு சோதனைகள்; TDD திறந்திருக்கும் அச்சு.
  • கட்டுப்பாடு — ஒரு அடிப்படை மற்றும் தோல்வியடைய அல்லது வழிநடத்த அதிகாரம். ¬C → கவனிக்கும் ஆனால் ஒருபோதும் தடுக்காத டெலிமெட்ரி.

இரண்டு ஆட்சி முறைகள்:

  • நிலையானது (குறியீட்டை சரிபார்க்கவும், CI இல்) — சோர்வு, வேறுபாடு, உருமாற்றம், உள்ளீட்டு-மாற்றம், பண்புக்கூறு அடிப்படையிலான, செயல்திறன்/கசிவு வாயில்கள். கண்டறியும்.
  • டைனமிக் (பறக்கும் நிலையில் உள்ள நிலையை சரிபார்க்கவும், உற்பத்தியில்) — நிலை-எல்லை ஒப்பந்தங்கள், ஸ்கீமா/மாறாத பாதுகாப்பு, முந்தைய சுழல்களுக்கு நிராகரித்தல். தடுப்பு + திருத்தும்.

முதலில் வலிமையான, மலிவானதை அடையுங்கள்: வரையறுக்கப்பட்ட டொமைன் → அதை முழுமையாகப் பயன்படுத்துங்கள்; தலைகீழ் → சுற்று-பயணம் decode(encode(x))==x; குறிப்பு → வேறுபாடு; உருமாற்ற-மாறாத → உருமாற்றம்; அறியப்பட்ட-நல்ல உள்ளீட்டை சிதைக்க முடியும் → உள்ளீட்டு-மாற்றம் (ஒரு கவரேஜ் எண், ஒரு பூலியன் அல்ல); இல்லையெனில் → பண்புக்கூறு அடிப்படையிலான + சுருக்குதல். ஆசிரியர் எழுதாத ஆரக்கிளை விரும்புங்கள் — ஆரக்கிள் இல்லாதது, தவறாக இருக்கக்கூடிய ஒரு "எதிர்பார்க்கப்பட்ட மதிப்பு" ஐ விட சிறந்தது.

உள்ளீட்டு-மாற்றம், குறிப்பாக: அறியப்பட்ட-செல்லுபடியாகும் உள்ளீட்டின் ஒவ்வொரு பிட்/பைட்டையும் புரட்டி, சரிபார்ப்பவர் இப்போது அதை நிராகரிக்கிறார் என்று உறுதிப்படுத்துங்கள்; கண்டறியப்பட்ட பகுதி, வடிவத்தின் எவ்வளவு பகுதியை அது உண்மையில் கட்டுப்படுத்துகிறது என்பதை அளவிடுகிறது — "நான் முழு வடிவத்தையும் சரிபார்க்கிறேன்" என்பதை யாரும் கற்பனை செய்ய முடியாத ஒரு எண்ணாக மாற்றுகிறது. நேர்மையாக இருங்கள்: ஒரு குறிப்பிட்ட கார்பஸ் உடன் இணைக்கவும் (அனைத்து செல்லுபடியாகும் உள்ளீடுகளும் தேர்ச்சி பெற வேண்டும், இல்லையெனில் அனைத்தையும் நிராகரிக்கும் சரிபார்ப்பவர் 100% மதிப்பெண் பெறுவார்), மற்றும் கண்டறியப்பட வேண்டிய பகுதிகளை மட்டுமே மதிப்பெண் பெறுங்கள் (பேடிங் / CRC-விலக்கப்பட்ட பைட்டுகள் சட்டபூர்வமான புறக்கணிக்கப்பட வேண்டியவை).

பாதுகாப்பு அரண்கள்: சாதாரண சரிபார்ப்பு பொதுவாக I (ஒரு முகவர் ஸ்கீமாவை வரையறுக்கிறது மற்றும் அதற்கு எதிராக உருவாக்குகிறது) அல்லது C (அது பதிவு செய்கிறது) இல் தோல்வியடைகிறது. எச்சரிக்கை-மட்டும் கண்காணிப்பு M-F-I ஆனால் ¬C — டெலிமெட்ரி, ஒரு கேட் அல்ல; கட்டமைப்பை தோல்வியடையச் செய்யும் ஒரு சோதனை முழு MFIC. ஆதாரம் அரசியலமைப்பு ரீதியானது — ஒரு தடயம் இல்லாத கட்டுப்பாடு இயங்கவில்லை; அதன் அளவீட்டு வரலாற்றை கமிட் + வன்பொருள் மூலம் பதிப்பு செய்யவும். புள்ளிவிவர உறுப்பினர்கள் நியாயமான உறுதிப்பாட்டை தருகிறார்கள், ஆதாரம் அல்ல — அங்கீகரிக்கப்பட்ட தரநிலை, ஒரு குறைபாடு அல்ல.

முந்தைய கலை: மாற்றம், உருமாற்றம், வேறுபாடு, பண்புக்கூறு அடிப்படையிலான சோதனை, தவறு ஊசி (மென்பொருள் V&V); கடமைகளைப் பிரித்தல், தடுப்பு/கண்டறியும்/திருத்தும் கட்டுப்பாடுகள், தணிக்கை தடங்கள், கட்டுப்பாடுகளின் சோதனை, நியாயமான உறுதிப்பாடு (COSO / Sarbanes-Oxley).

இது வேலை செய்யும் சுருக்கம். முழு தொழில்நுட்ப சிகிச்சை — ஆழமான சுதந்திர அச்சு, தயாரிப்பாளர்/அங்கீகரிப்பவர் முறை, கொள்கையிலிருந்து தடுக்கும் வாயில்கள் வரை குறியாக்க கட்டுப்பாடுகள் வரை அதிகரிப்பு, மற்றும் ஐந்து வேலை செய்யப்பட்ட எடுத்துக்காட்டுகள் — முழுமையான MFIC முறையியலில் உள்ளது.
