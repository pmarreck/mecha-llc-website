署名。

MFIC — 机械可证伪独立控制 正是这样一种纪律：在每个交接点进行独立检查，其判断来自合同或数据，绝不来自生产者的说法，并拥有拒绝或中止的权力。它是 萨班斯-奥克斯利法案 (COSO) 背后的内部控制模型 — 职责分离、预防性和检测性控制、审计追踪、合理保证 — 将 LLM（或匆忙的人类）视为新的不可信方。

对于受监管、高风险的工作，这就是“AI 说的”与您在审计中可以辩护的答案之间的区别。这是 Mecha 构建一切的准则——也是这里验证结果附带门槛而非承诺的原因。

如何信任一个易犯错的作者（LLM 或匆忙的人类）可能悄悄损坏的代码或数据。TDD 的红色阶段只给出 F（一个测试 可以 触发）；MFIC 添加了其他三个。它是 COSO / 萨班斯-奥克斯利内部控制模型，将 LLM 视为新的不可信方。

定义: 在 交接边界 处的独立检查，其判断来自合同或数据 — 绝不来自生产者的说法 — 并拥有拒绝、中止或引导的权力。

试金石: 如果同一个代理编写了检查和被检查的东西，它能否在错误工作的情况下通过？ 是 → 可玩弄，不是 MFIC。否 → MFIC。

每个词都承载着意义:

  • 机械地 — 案例由机器扫描，而非人工挑选。¬M → 遗漏错误。
  • 可证伪 — 每个案例都是一个尖锐的反驳，你无法预先安排。¬F → 空洞的绿色测试，或弱预言（“不崩溃”隐藏了错误输出）。
  • 独立 — 真理来源与生产者在因果上独立（≡ 职责分离: 制造者 ≠ 检查者）。¬I → 共享一个盲点的串通测试；TDD 留下的轴线。
  • 控制 — 一个基线 加上 失败或引导的权力。¬C → 观察但不阻止的遥测。

两种制度:

  • 静态（在 CI 中验证代码）— 穷举、差分、变异、输入变异、基于属性、性能/内存泄漏门。检测性。
  • 动态（在生产中验证飞行中的状态）— 阶段边界合同、模式/不变性保持、拒绝到上一循环。预防性 + 纠正性。

首先选择最强、最便宜的: 有限域 → 穷举；逆 → 往返 decode(encode(x))==x；参考 → 差分；变换不变 → 变异；可以损坏已知良好输入 → 输入变异（一个 覆盖率数字，而不是布尔值）；否则 → 基于属性 + 缩小。优先选择作者未编写的预言 — 无预言胜过作者编写的“预期值”，后者本身可能出错。

具体来说，输入变异: 翻转已知有效输入的每个位/字节，并断言验证器现在 拒绝 它；检测到的比例衡量了它实际约束了多少格式 — 将“我验证整个格式”变成一个没有人能凭空想象的数字。保持诚实：与 特异性语料库 配对（所有有效输入必须通过，否则拒绝一切的检查器得分 100%），并且只对 必须检测 区域评分（填充/CRC 排除的字节是合法的无关紧要）。

护栏: 普通验证通常在 I（一个代理定义模式 并 根据它进行生产）或 C（它只记录）上失败。一个只警告的监视器是 M-F-I 但 ¬C — 遥测，而不是门；一个 使构建失败 的检查是完整的 MFIC。证据是构成性的 — 没有追踪的控制没有运行；按提交 + 硬件版本化其测量历史。统计成员提供 合理保证，而不是证明 — 公认的标准，而不是缺陷。

现有技术: 变异、变异、差分、基于属性的测试、故障注入（软件 V&V）；职责分离、预防性/检测性/纠正性控制、审计追踪、控制测试、合理保证（COSO / 萨班斯-奥克斯利）。

这是工作摘要。完整的技术处理——深入探讨独立性轴、生产者/审批者模式、从策略升级到阻塞门再到加密控制，以及五个实际示例——都包含在完整MFIC方法论中。
