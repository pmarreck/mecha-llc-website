Mga Kaisipan · Metodolohiya

Pagtitiwala sa output ng AI nang sapat
upang ilagay ang iyong pangalan dito.

MFIC — Ang Mechanically-Falsifiable Independent Control ay isang disiplina para sa eksaktong iyon: mga independiyenteng pagsusuri sa bawat handoff na nagmula sa kanilang hatol mula sa kontrata o sa data, hindi kailanman mula sa sinasabi ng producer, at may kapangyarihang tanggihan o ihinto. Ito ang internal-control model sa likod ng Sarbanes-Oxley (COSO) — paghihiwalay ng mga tungkulin, preventive at detective controls, audit trails, reasonable assurance — na ang LLM (o isang nagmamadaling tao) ang bagong hindi pinagkakatiwalaang partido.

Para sa regulated, high-stakes na trabaho, iyon ang pagkakaiba sa pagitan ng “sinabi ng AI” at isang sagot na maaari mong ipagtanggol sa ilalim ng audit. Ito ang disiplina sa likod ng lahat ng binuo ng Mecha — at ang dahilan kung bakit ang resulta ng pag-verify dito ay may gate, hindi isang pangako.

Paano magtiwala sa code o data na maaaring tahimik na sirain ng isang may-akda na nagkakamali — isang LLM, o isang nagmamadaling tao. Ang red phase ng TDD ay nagbibigay lamang ng F (isang test ay maaaring mag-fire); MFIC ay nagdaragdag ng iba pang tatlo. Ito ang COSO / Sarbanes-Oxley internal-control model, na ang LLM ang bagong hindi pinagkakatiwalaang partido.

Depinisyon: isang independiyenteng pagsusuri sa isang handoff boundary na nagmula sa hatol nito mula sa kontrata o sa data — hindi kailanman mula sa account ng producer nito — at may kapangyarihang tanggihan, ihinto, o gabayan.

Litmus: kung ang parehong ahente ang sumulat ng parehong pagsusuri at ang bagay na sinuri, maaari ba itong pumasa sa maling trabaho? Oo → mapaglalaruan, hindi MFIC. Hindi → MFIC.

Bawat salita ay load-bearing:

  • Mechanically — mga kaso na sinuri ng makina, hindi pinili ng kamay. ¬M → mga bug sa pagtanggal.
  • Falsifiable — bawat kaso ay isang matinding pagtanggi na hindi mo maaaring ayusin nang maaga. ¬F → walang laman na green tests, o mahinang oracles ("hindi bumabagsak" na nagtatago ng maling output).
  • Independent — pinagmulan ng katotohanan na causally independent ng producer (≡ paghihiwalay ng mga tungkulin: maker ≠ checker). ¬I → collusive tests na nagbabahagi ng isang blind spot; ang axis na iniiwan ng TDD na bukas.
  • Control — isang baseline plus kapangyarihang bumagsak o gumabay. ¬C → telemetry na nagmamasid ngunit hindi kailanman humaharang.

Dalawang rehimen:

  • Static (i-verify ang code, sa CI) — pagkaubos, differential, metamorphic, input-mutation, property-based, perf/leak gates. Detective.
  • Dynamic (i-verify ang estado sa flight, sa prod) — stage-boundary contracts, schema/invariant preservation, reject-to-previous loops. Preventive + corrective.

Abutin ang pinakamalakas, pinakamura muna: finite domain → ubusin ito; inverse → round-trip decode(encode(x))==x; reference → differential; transform-invariant → metamorphic; maaaring sirain ang kilalang-magandang input → input-mutation (isang coverage number, hindi isang bool); kung hindi → property-based + shrink. Mas gusto ang oracle na hindi isinulat ng may-akda — ang oracle-free ay mas mahusay kaysa sa isang authored "expected value" na maaaring mali mismo.

Input-mutation, partikular: baligtarin ang bawat bit/byte ng isang kilalang-valid na input at igiit na ang verifier ngayon ay tinatanggihan ito; ang bahagi na natukoy ay sumusukat kung gaano karami sa format ang aktwal nitong pinipigilan — ginagawang isang numero ang "I validate the whole format" na walang sinuman ang makakapag-hallucinate. Panatilihin itong tapat: ipares sa isang specificity corpus (lahat ng valid na input ay dapat pumasa, kung hindi, ang isang reject-everything checker ay nakakakuha ng 100%), at i-score lamang ang must-detect na mga rehiyon (ang padding / CRC-excluded bytes ay lehitimong don't-cares).

Guardrails: ang ordinaryong validation ay karaniwang nabibigo sa I (isang ahente ang nagtatakda ng schema at gumagawa laban dito) o C (ito ay nagla-log lamang). Ang isang warn-only monitor ay M-F-I ngunit ¬C — telemetry, hindi isang gate; isang pagsusuri na nagpapabagsak sa build ay buong MFIC. Ang ebidensya ay constitutive — isang kontrol na walang trail ay hindi tumakbo; i-version ang historya ng pagsukat nito sa pamamagitan ng commit + hardware. Ang mga statistical members ay nagbibigay ng reasonable assurance, hindi patunay — ang kinikilalang pamantayan, hindi isang kakulangan.

Prior art: mutation, metamorphic, differential, property-based testing, fault injection (software V&V); segregation of duties, preventive/detective/corrective controls, audit trail, test of controls, reasonable assurance (COSO / Sarbanes-Oxley).

Ito ang working summary. Ang buong teknikal na paggamot — ang independence axis sa lalim, ang producer/approver pattern, ang escalation mula sa patakaran hanggang sa pagharang ng mga gate hanggang sa cryptographic controls, at limang nagawang halimbawa — ay matatagpuan sa kumpletong MFIC metodolohiya.
