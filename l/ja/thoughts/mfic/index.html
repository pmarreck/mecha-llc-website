MFIC — 機械的に反証可能な独立した管理は、まさにそのための規律です。すべての引き渡しにおいて、契約またはデータから判断を導き出し、生産者の言い分に決して左右されず、拒否または停止する権限を持つ独立したチェックです。これは、サーベンス・オクスリー法 (COSO) の背後にある内部統制モデル — 職務の分離、予防的および発見的統制、監査証跡、合理的な保証 — であり、LLM（または急いでいる人間）を新たな信頼できない当事者と見なします。

規制された高リスクの作業では、それが「AIがそう言った」と、監査で弁護できる回答との違いです。それはMechaが構築するすべてのものの背後にある規律であり、ここでの検証結果が約束ではなくゲートを伴う理由です。

誤りやすい作成者（LLM、または急いでいる人間）が密かに破損させる可能性のあるコードやデータを信頼する方法。TDDのレッドフェーズはF（テストが発火すること）しか提供しません。MFICは残りの三つを追加します。これはCOSO / サーベンス・オクスリー法の内部統制モデルであり、LLMが新しい信頼できない当事者となります。

定義: 引き渡し境界における独立したチェックで、その判断を契約またはデータから導き出し — 決して生産者の説明からではなく — 拒否、停止、または指示する権限を持つもの。

リトマス試験: 同じエージェントがチェックとチェックされるものの両方を書いた場合、間違った作業でも合格できるか？ はい → 不正操作可能、MFICではない。いいえ → MFIC。

各単語が重要です:

  • 機械的に — ケースは機械的にスキャンされ、 手作業で選ばれていない。¬M → 欠落バグ。
  • 反証可能 — 各ケースは、事前に手配できない 痛烈な反論。¬F → 空虚なグリーンテスト、または弱いオラクル（「クラッシュしない」が間違った出力を隠す）。
  • 独立して — 真実のソースが生産者から因果的に独立している （≡ 職務の分離: 作成者 ≠ チェック者）。¬I → 共通の盲点を持つ共謀テスト。TDDが未解決の軸。
  • 管理 — ベースラインに加えて 失敗または指示する権限。¬C → 監視するだけでブロックしないテレメトリー。

二つの体制:

  • 静的（CIでコードを検証） — 網羅的、 差分、変形、入力変異、プロパティベース、パフォーマンス/リーク ゲート。発見的。
  • 動的（本番環境で実行中の状態を検証） — ステージ境界契約、スキーマ/不変条件の維持、 以前のループへの拒否。予防的 + 是正的。

最も強力で安価なものから最初に手を付ける: 有限 ドメイン → 網羅する。逆関数 → ラウンドトリップ decode(encode(x))==x。参照 → 差分。変換不変 → 変形。既知の良好な入力を破損できる → 入力変異（カバレッジ数であり、ブール値ではない）。その他 → プロパティベース + 縮小。作成者が書かなかったオラクルを優先する — オラクルなしは、それ自体が間違っている可能性のある作成された「期待値」よりも優れている。

入力変異、具体的には: 既知の有効な入力の各ビット/バイトを反転させ、検証者がそれを拒否することをアサートします。検出された割合は、それが実際にフォーマットのどれだけを制約しているかを測定します — 「フォーマット全体を検証する」を誰も幻覚を見ることができない数値に変えます。正直に保つ: 特異性コーパス（すべての有効な入力が合格しなければならない、そうでないとすべてを拒否するチェッカーは100%をスコアする）と組み合わせ、検出必須領域（パディング/CRC除外バイトは正当な無視対象）のみをスコアします。

ガードレール: 通常の検証は、I（一人のエージェントがスキーマを定義し、それに対して生成する）またはC（ログのみを記録する）で失敗することがよくあります。警告のみのモニターはM-F-Iですが、¬C — テレメトリーであり、ゲートではありません。ビルドを失敗させるチェックは完全なMFICです。証拠は構成的 — 記録のない制御は実行されませんでした。コミットとハードウェアによってその測定履歴をバージョン管理します。統計的メンバーは合理的な保証を提供し、証明ではありません — 認識された標準であり、欠陥ではありません。

先行技術: 変異、変形、差分、 プロパティベースのテスト、フォールトインジェクション（ソフトウェアV&V）；職務の分離、予防/発見/是正管理、監査証跡、管理テスト、合理的な保証（COSO / サーベンス・オクスリー法）。

これは作業中の要約です。完全な技術的解説 — 独立性の軸の詳細、プロデューサー/承認者パターン、ポリシーからブロッキングゲート、暗号化制御へのエスカレーション、そして五つの実例 — は完全なMFIC方法論に記載されています。
