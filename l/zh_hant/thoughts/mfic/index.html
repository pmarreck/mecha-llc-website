MFIC — 機械可證偽獨立控制 正是為此而設的紀律：在每個交接點進行獨立檢查，其判斷來自合約或數據，絕不來自生產者的說法，並擁有拒絕或停止的權力。這是 薩班斯-奧克斯利法案 (COSO) 背後的內部控制模型 — 職責分離、預防性和偵測性控制、審計追蹤、合理保證 — 將 LLM（或匆忙的人類）視為新的不可信方。

對於受監管、高風險的工作，這就是「AI 說的」與您在審計下可以辯護的答案之間的區別。這是 Mecha 構建一切背後的紀律 — 也是這裡的驗證結果帶有閘道而非承諾的原因。

如何信任一個易犯錯的作者 — LLM，或一個匆忙的 人類 — 可能悄悄破壞的程式碼或數據。TDD 的紅色階段只提供 F（一個測試可以觸發）；MFIC 添加了其他 三個。這是 COSO / 薩班斯-奧克斯利內部控制模型，將 LLM 視為新的不可信方。

定義： 在 交接 邊界 進行的獨立檢查，其判斷來自合約或數據 — 絕不來自生產者的說明 — 並擁有拒絕、停止或引導的權力。

試金石： 如果同一個代理人同時編寫檢查 和被檢查的內容，它能否在錯誤的工作下通過？ 是 → 可操縱，不是 MFIC。否 → MFIC。

每個詞都承載著意義：

  • 機械地 — 案例由機器掃描，而非 手工挑選。¬M → 遺漏錯誤。
  • 可證偽 — 每個案例都是一個尖銳的反駁，您 無法預先安排。¬F → 空洞的綠色測試，或弱預言機（「不會 崩潰」隱藏了錯誤輸出）。
  • 獨立 — 真實來源在因果上獨立於 生產者（≡ 職責分離：製作者 ≠ 檢查者）。¬I → 串通測試共享一個盲點；TDD 留下的軸線。
  • 控制 — 一個基準 加上 失敗或引導的權力。¬C → 觀察但不阻止的遙測。

兩種機制：

  • 靜態（在 CI 中驗證程式碼）— 窮舉、 差異、變異、輸入變異、基於屬性、性能/洩漏 閘道。偵測性。
  • 動態（在生產中驗證運行中的狀態）— 階段邊界合約、模式/不變式保存、 拒絕到上一個循環。預防性 + 糾正性。

首先尋求最強大、最便宜的： 有限 域 → 窮舉它；逆 → 往返 decode(encode(x))==x；參考 → 差異； 轉換不變 → 變異；可以破壞已知良好輸入 → 輸入變異（一個 覆蓋率數字，而不是布林值）；否則 → 基於屬性 + 縮小。偏愛作者未編寫的預言機 — 無預言機勝過作者編寫的「預期值」，因為它本身可能就是錯誤的。

特別是輸入變異： 翻轉已知有效輸入的每個位元/位元組，並斷言驗證器現在拒絕它；檢測到的比例衡量了它實際約束了多少格式 — 將「我驗證整個格式」變成一個無人能憑空捏造的數字。保持誠實：與特異性語料庫配對（所有有效輸入都必須通過，否則一個拒絕一切的檢查器得分為100%），並且只對必須檢測區域進行評分（填充/CRC排除的位元組是合法的無關緊要）。

護欄： 普通驗證通常會失敗 I（一個代理定義模式並根據它進行生產）或 C（它只記錄）。一個僅警告的監視器是 M-F-I 但 ¬C — 遙測，而不是閘道；一個導致建置失敗的檢查是完整的MFIC。證據是構成性的 — 沒有軌跡的控制沒有運行；按提交 + 硬體版本化其測量歷史。統計成員提供 合理保證，而不是證明 — 這是公認的標準，而不是缺陷。

現有技術： 變異、變異、差異、 基於屬性的測試、故障注入（軟體 V&V）；職責分離、 預防性/偵測性/糾正性控制、審計追蹤、控制測試、 合理保證（COSO / 薩班斯-奧克斯利）。

這是工作摘要。完整的技術處理 — 深入的獨立性軸線、生產者/批准者模式、從政策到阻擋閘道再到加密控制的升級，以及五個實例 — 都在完整MFIC方法論中。
